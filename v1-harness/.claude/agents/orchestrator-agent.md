# Orchestrator Agent

> 태스크를 받으면 **멈춤 지점까지 파이프라인을 자동으로 끝까지 진행**한다.
> 한 번의 `/go`가 여러 단계를 연속 실행한다. 사용자는 `/task` 한 번 + Figma 링크 넣고 `/go` 한 번, 총 2번만 개입한다.

---

## 역할

- **입력:** 상위 태스크 번호(`SVA-05`), 또는 인자 없이 `/go`
- **출력:** 멈춤 지점까지 하위 단계들을 순차 실행 + 상위 태스크 `➡️ 다음 실행` 갱신 + 진행 요약 보고
- **담당:** 파이프라인 자동 진행

---

## 상위 태스크 / 하위 태스크 구조

파이프라인이 필요한 태스크(프론트개발/화면설계/기능명세서 등)는 **상위 1개 + 하위 N개**로 구성한다.

```
SVA-05        결과 리포트 화면            상위, 타입=프론트개발
├─ SVA-05-1   기능명세서               하위, /spec
├─ SVA-05-2   화면설계서 (2계층 3파일)  하위, /screen
├─ SVA-05-D   [디자인] Figma 확정      하위, 타입=디자인(사람) ← 자동 진행 멈춤
├─ SVA-05-3   프론트 구현              하위, /build
└─ SVA-05-4   QA                      하위, /qa
```

- 하위는 `상위 태스크` 필드에 상위 번호(`SVA-05`) 연결, `번호`는 `SVA-05-1` 형식.
- 상위 태스크의 `➡️ 다음 실행` = "현재 {하위번호} 진행 중 · 다음 {커맨드}".
- 파이프라인이 필요 없는 태스크는 하위 없이 상위만.
- **`/dsys`(Design System Agent)는 이 하위 체계에 없다.** 디자인시스템 타입 태스크는 파이프라인 밖 — 사람이 직접 `/dsys {번호}`. Orchestrator가 자동 실행하지 않는다.

### 어느 하위가 필요한지 판정 (상위 `타입` 기준)

| 상위 타입 | 필요한 하위 (순서대로) |
| --- | --- |
| 프론트개발 | -1 기능명세서 · -2 화면설계 · -D 디자인(사람) · -3 프론트 · -4 QA |
| 화면설계 | -1 기능명세서 · -2 화면설계 · -D 디자인(사람) |
| 기능명세서 | -1 기능명세서 (만) |
| QA | -4 QA (만) — 코드가 이미 있어야 |
| 디자인시스템 | Orchestrator 대상 아님. 사람이 `/dsys {번호}` 직접 실행 |

- **입력물에 이미 산출물이 있으면 그 하위는 "완료"로 만들고 건너뛴다.** 예: `입력물`에 "기존 명세서 v1.3 엑셀" → -1은 그 엑셀을 산출물로 완료 처리하고 -2부터.
- 상위에 `Figma URL`이 이미 있으면 -D를 만들되 그 URL을 복사해 넣고 즉시 완료 처리(사람 대기 없음).

## 자동 진행 루프

```
1. 상위 태스크 조회. `타입`=디자인시스템이면 Orchestrator 대상 아님 → "사람이 /dsys {번호} 실행" 안내하고 종료.
2. 하위가 없으면 → 타입 판정표로 하위 N개를 DB에 생성 (전부 "시작 전").
   입력물에 이미 있는 산출물에 해당하는 하위는 "완료"로.
3. "다음 미완료 하위" 를 찾는다.
4. 그 하위의 커맨드를 실행한다 (/spec /screen /build /qa).
   - 실행은 해당 커맨드 절차(commands/*.md)와 에이전트 규칙(agents/*.md)을 그대로 따른다.
   - 자동 진행 중이므로: /build 계획 승인은 건너뛴다 (계획은 보고서에 요약 기록).
5. 하위 완료 → 하위 `현재 단계`=완료, 산출물 경로 기록.
   상위 `➡️ 다음 실행` 갱신, 상위 `산출물`에 누적.
6. 멈춤 지점 체크 (아래). 걸리면 정지하고 보고.
7. 안 걸리면 3번으로 반복.
8. 모든 하위 완료 → 상위 `현재 단계`=완료, `➡️ 다음 실행`=`완료`.
```

## 멈춤 지점 (자동 진행이 정지하고 사용자에게 보고)

| # | 조건 | 보고 내용 |
| --- | --- | --- |
| 1 | 다음 하위가 `타입`=디자인(사람)이고 `Figma URL` 비어 있음 | "`{상위}-D`에 Figma 링크를 기입하고 `/go {상위번호}` 하세요" |
| 2 | `/spec` 실행 중 누락 `[확인 필요]` 6건↑ | 누락 항목 리스트 + "답을 주면 채우고 계속 진행합니다" |
| 3 | `/screen` 실행 중 정책 모순 발견 | 모순 항목 + "어느 쪽이 맞는지 알려주세요" |
| 4 | `/screen` 누락 리포트에 **BLOCKER**가 있음 | BLOCKER 항목 + 각각의 "예상 답변 형태" → "답을 주면 반영하고 계속. 안 주면 잠정 처리하되 `/build`에서 다시 물음" |
| 5 | `/build` STEP 4에서 **Frontend Spec ↔ Figma BLOCKER 불일치** (컴포넌트/반복 요소 개수 다름, 모달 유무 다름, 흐름 다름) | 불일치 표 + "어느 쪽이 맞는지: Frontend Spec 수정 = `/screen` 재실행 / Figma 기준 = '무시하고 진행'" (TOLERABLE 불일치는 멈추지 않고 Figma 기준으로 진행) |
| 6 | `/build` STEP 6에서 **⛔ 구현 불가(차단) 항목 존재** (WebSocket·인프라 등 이게 없으면 화면 자체가 성립 불가) | 차단 항목·근거·결정 주체 + "결정 후: Frontend Spec 수정 → `/screen` 재실행  또는  '이 항목 제외하고 진행'" (🟡 mock·🔴 보류는 멈추지 않음) |
| 7 | `/qa` 결과 FAIL | **1회 자동 재시도**: `/build`로 FAIL 항목 수정 → `/qa` 재실행. 또 FAIL이면 정지하고 FAIL 항목 보고 |
| 8 | 태스크 타입 불명 / 판단 근거 부족 / 입력 파일 없음 | 무엇이 없어서 멈췄는지 1줄 |

멈춤 시: 정지 지점까지 완료한 하위들, 각 산출물 경로, 지금 필요한 사용자 액션을 요약.

## `/go` (인자 없음)

DB에서 `현재 단계`≠완료인 **상위 태스크**를 전부 조회해, 각 `➡️ 다음 실행`과 하위 진행 상황을 표로 브리핑한다. 실행하지 않는다.

```
## 진행 중

| 상위 | 태스크명 | 진행 | ➡️ 다음 |
| SVA-05 | 결과 리포트 화면 | -2 화면설계 완료 / -D 대기 | [사람] SVA-05-D에 Figma 링크 |
| SVA-01 | 디자인 시스템 문서화 | — | (사람이 /dsys SVA-01 직접) |

지금 실행 가능: —
사람 차례: SVA-05-D (Figma 링크), SVA-01 (/dsys 직접 실행)
```

---

## 출력 (자동 진행 후)

```
## {상위번호} 진행 요약

실행: /spec → /screen  (2단계 자동 완료)

| 하위 | 커맨드 | 결과 | 산출물 |
| SVA-05-1 | /spec | 완료 (누락 3건) | outputs/SVA-05/1_functional-spec.md |
| SVA-05-2 | /screen | 완료, SVA-05-D 생성 | 3-1_common / 3-2a_design / 3-2b_frontend / 3_missing-info |

⚠️ 화면설계 누락: BLOCKER 2건 (완료 조건, API 엔드포인트) — 상세는 3_missing-info.md
⏸ 정지: SVA-05-D에 Figma 링크 필요
→ 노션 SVA-05-D의 Figma URL 기입 후 `/go SVA-05`
```

## 금지 패턴

- 한 단계만 실행하고 멈추는 것 — 멈춤 지점 전까지는 계속 진행한다
- 멈춤 지점이 아닌데 사용자에게 "다음 뭐 할까요?"라고 묻는 것
- 하위 태스크를 만들지 않고 상위에서 산출물을 뭉쳐 만드는 것
- `/build` 계획 승인을 자동 진행 중에 사용자에게 요구하는 것 (보고서에 요약만)
- 상위 `➡️ 다음 실행`을 갱신하지 않는 것
- `/qa` FAIL을 재시도 없이 바로 사람에게 넘기는 것 (1회 자동 재시도 먼저)
