# origin — 출발점이 된 요청서 프롬프트

이 체계는 기업 프로젝트에서 Claude Code에 화면 구현을 맡길 때 직접 쓰던 **요청서 프롬프트**에서 출발했습니다.
AI가 요청하지 않은 파일까지 고치거나, 없는 라이브러리를 설치하거나, 이미 있는 컴포넌트를 새로 만드는 문제가 반복되자 지시문이 점점 구체화됐습니다.

```
초기 지시문 (2종)  →  상황별 템플릿 (3종)  →  v1 하네스 (에이전트 7개)  →  v2 템플릿 (커맨드 + 공통 규칙)
```

v2에서는 세 템플릿에 똑같이 반복되던 "주의" 항목을 공통 규칙 한 곳([`v2-template/.claude/rules/frontend.md`](../v2-template/.claude/rules/frontend.md))으로 모으고, 상황별 빈칸만 템플릿으로 남겼습니다.

| 원본 템플릿 | v2에서 |
|---|---|
| 확실한 명령 | `/build` — 진행 방식·구현 범위·디자인 기준을 화면설계서가 채움 |
| 이슈 해결 | `/fix` + `templates/issue.md` |
| 요구사항 기본값 | `/fe` + `templates/request.md` |
| 세 템플릿 공통 "주의" | `rules/frontend.md` 한 곳 |

## 1. 초기 지시문

### 1-a
```
10년차 프론트엔드 리드 개발자 관점에서 작업해주세요.

작업 전
- 프로젝트 구조 확인
- 기존 컴포넌트 확인
- 구현 계획 설명 후 진행

주의
- 요청 범위 외 파일 수정 금지
- API/서버 로직 수정 금지
- 라이브러리 추가 금지
- 기존 공통 컴포넌트 우선 사용
- 디자인 시스템(Color/Typography/Spacing) 준수

작업 완료 후
- 수정 파일 목록
- 변경 내용 요약
- 영향 범위 설명
정리해주세요.
```

### 1-b (짧은 버전)
```
10년차 프론트엔드 리드 개발자 관점에서 작업해주세요.

중요:
- 요청한 범위만 수정
- 다른 파일 건드리지 말 것
- 라이브러리 추가 금지
- 기존 컴포넌트 재사용
- 구현 전 계획 설명
- 구현 후 수정 파일 요약
```

## 2. 상황별 템플릿

세 템플릿 모두 아래 **공통 주의**를 붙여 썼습니다.

```
주의:
- 먼저 현재 프로젝트 구조와 사용 가능한 라이브러리를 확인하고, 가장 적절한 구현 계획을 설명한 뒤 진행
- API/서버 로직은 건드리지 말 것
- 새 라이브러리 설치는 임의로 하지 말 것
- 기존 공통 컴포넌트가 있으면 반드시 재사용
- 구현 후 수정 파일과 동작 방식을 요약해줘
- 질문 필요한 부분은 구현 전에 한꺼번에 리스트로 정리해줘.
```
