# 공통 규칙

기능명세서 → 화면설계서 → (사람이 Figma 확정) → 프론트 코드를 **템플릿 빈칸 채우기**로 만든다.
사람이 단계마다 직접 실행한다: `/spec` → `/screen` → `/build`. 구현 후 이슈는 `/fix`, 명세 없는 작은 작업은 `/fe`.

## 원칙
1. **소스에 있는 것만 옮긴다.** 없는 값은 지어내지 말고 `[확인 필요: 누가 답하나]`로 남긴다.
2. **템플릿의 빈칸만 채운다.** 표 구조·항목 이름을 바꾸거나 설명을 덧붙이지 않는다. 해당 없음은 `N/A: 사유`.
3. **지정된 입력만 읽는다.** 각 커맨드가 정한 파일·섹션 외에는 열지 않는다.
4. **자기 단계 산출물만 만든다.** 이전 단계 파일은 수정하지 않는다.
5. **디자인 값은 토큰 이름으로.** `rules/tokens.md`에 있는 이름만 쓴다. hex·px 하드코딩 금지.

## 멈추는 경우
누락 리포트에 `⛔ 지금 결정 필요`가 1건이라도 있으면 다음 단계로 가지 않고 그 항목만 묻는다.
- 이게 없으면 화면 자체가 성립하지 않는다 (핵심 인터랙션, 인프라 부재)
- 정책 키워드(권한·금액·날짜·삭제·제한)가 걸렸는데 정책이 비어 있다

그 외 누락은 `🔴 나중에 결정`으로 적고 placeholder로 진행한다.

## 파일 위치
- 템플릿: `.claude/templates/`
- 프론트 작업 규칙 (`/build` · `/fix` · `/fe` 공통): `.claude/rules/frontend.md`
- 산출물: `outputs/{화면ID}/` — `spec.md` · `screen.md` · `missing.md` · `build-report.md`
