# 프론트엔드 작업 규칙

`/build` · `/fix` · `/fe`가 공통으로 따른다. 10년차 프론트엔드 리드 개발자 관점에서 작업한다.

## 작업 전
- 프로젝트 구조와 사용 가능한 라이브러리(`package.json`)를 확인한다.
- 기존 공통 컴포넌트를 확인한다.
- 구현 계획(변경할 파일, 재사용할 컴포넌트)을 설명하고 확인받은 뒤 진행한다.
- 질문이 필요한 부분은 구현 전에 한꺼번에 리스트로 정리한다.

## 주의
- 요청 범위 외 파일 수정 금지
- API/서버 로직 수정 금지
- 라이브러리 추가 금지
- 기존 공통 컴포넌트가 있으면 반드시 재사용
- 디자인 시스템(Color/Typography/Spacing) 준수 — `rules/tokens.md`의 이름만 사용

## 작업 완료 후
`templates/build-report.md` 형식으로 정리한다: 수정 파일 목록 · 변경 내용과 동작 방식 · 영향 범위.
