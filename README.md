# AI Planning Agent — 템플릿 기반 기획·디자인·개발 컨텍스트 체계

> 개인 프로젝트 · 2026.09 · 설계 1인 (Claude Code 커맨드·템플릿)

기업 프로젝트에서 AI 도구로 **화면 설계부터 프론트엔드 개발까지 2주 만에 끝낸 방식**(약 1개월 → 2주)을, Claude Code가 같은 품질로 반복할 수 있도록 **템플릿과 컨텍스트 규칙으로 구조화**한 프로젝트입니다.

처음에는 에이전트 7개가 자동으로 이어 달리는 하네스 구조(v1)로 만들었지만, 혼자 쓰기에는 너무 무겁고 토큰이 많이 들어서 **핵심만 남긴 경량 구조(v2)로 다시 설계**했습니다.

> **공개 범위 안내**: 기업 프로젝트에서 출발한 결과물이라서, 해당 기업과 관련된 대외비 정보(고객사·서비스명, 기능명세서 원본, 디자인 시스템, Figma 파일, 실제 산출물과 코드)는 모두 제외했습니다. 디자인 토큰과 예시는 가상의 값입니다. 이 때문에 그대로 실행하면 입력 파일이나 디자인 규칙이 없어 오류가 나거나 결과가 불완전할 수 있습니다.

## 왜 만들었나

회사에서 프론트엔드 전담 인력 없이 기획·디자인·개발을 혼자 맡으면서, ChatGPT로 Claude Code 요청서를 쓰고 Claude Code로 화면을 구현하는 방식을 정립했습니다. 그런데 요청서를 매번 손으로 쓰다 보니 같은 문제가 반복됐습니다.

- AI가 수정 범위를 넓게 해석해서 요청하지 않은 파일까지 건드림
- 명세서에 없는 값을 AI가 그럴듯하게 지어냄
- 단계를 넘어가면서 앞 단계의 정책이 조용히 깨짐

그래서 요청서 프롬프트를 먼저 다듬었고([`origin/`](origin/)), 그다음 이를 Claude Code 체계로 옮겼습니다.

```
요청서 프롬프트 (초기 2종 → 상황별 3종)  →  v1 하네스 (에이전트 7개)  →  v2 템플릿 (커맨드 + 공통 규칙)
```

## v1 → v2: 하네스를 걷어내고 템플릿으로

| | v1 하네스 ([`v1-harness/`](v1-harness/)) | **v2 템플릿 ([`v2-template/`](v2-template/))** |
|---|---|---|
| 구조 | 에이전트 7개 + 오케스트레이터 자동 연결 + 노션 태스크 연동 | **커맨드 5개 + 템플릿 6개 + 공통 규칙**, 사람이 단계별 실행 |
| 공통 규칙 (`CLAUDE.md`) | 8,760자 | **846자** |
| 규칙 파일 | 17개, 54,996자 | **14개, 5,818자** |
| 한 화면을 만들 때 AI가 읽는 규칙·템플릿 | 92,002자 (6단계) | **7,015자 (3단계) — 92% 감소** |
| 누락 등급 | 4단계 (차단 · 정책 필수 · BLOCKER · QUALITY) | 2단계 (⛔ 지금 결정 · 🔴 나중에 결정) |
| 화면설계서 | 3개 파일 (공통 / 디자인용 / 개발용) | 1개 파일 (공통 + 개발 섹션) |
| QA | 별도 QA 에이전트 + 실패 시 자동 재시도 | 구현 보고서의 자체 점검표 |

> 수치는 각 단계가 읽는 규칙·템플릿 파일의 글자 수를 더한 값입니다 (두 버전 모두 단계마다 공통 규칙을 다시 읽는다고 가정). v1이 참조하던 디자인 규칙 문서(공개 제외)까지 포함하면 감소 폭은 96%입니다. 프로젝트 코드나 산출물 자체의 토큰은 포함하지 않았습니다.

**무엇을 남기고 무엇을 뺐나**

- **남긴 것 — 이 체계의 진짜 가치 두 가지**
  1. 산출물 형식: 기능명세서 · 화면설계서 · 누락 리포트 · 구현 점검표
  2. "없는 값은 지어내지 말고 `[확인 필요]`로 남긴다"는 규칙과, 결정이 필요할 때만 멈추는 기준
- **합친 것**: 상황별 요청서 3종에 똑같이 반복되던 "주의" 6줄을 공통 규칙 한 곳(`rules/frontend.md`)으로 모으고, 상황별 빈칸만 템플릿으로 남겼습니다.
- **뺀 것**: 자동 연결, 노션 연동, 규칙 위반 Tier, 디자이너용 명세, 별도 QA 에이전트. 혼자 쓸 때는 단계 사이에 사람이 확인하는 편이 더 싸고 확실했습니다.

토큰을 줄인 구체적인 방법은 [v2 README](v2-template/README.md#토큰을-줄인-방법)에 정리했습니다.

## 폴더 구성

| 폴더 | 내용 | 바로 보기 |
|---|---|---|
| [`origin/`](origin/) | **출발점** — 회사에서 직접 쓰던 Claude Code 요청서 프롬프트 (초기 지시문 2종 + 상황별 템플릿 3종) | [README](origin/README.md) |
| [`v1-harness/`](v1-harness/) | **기존 버전** — 에이전트 7개 + 커맨드 8개, 오케스트레이터가 단계를 자동으로 이어 실행 | [README](v1-harness/README.md) · [흐름 예시](v1-harness/examples/walkthrough.md) |
| [`v2-template/`](v2-template/) | **현재 버전** — 커맨드 5개 + 템플릿 6개 + 공통 규칙, 사람이 단계별 실행 | [README](v2-template/README.md) · [흐름 예시](v2-template/examples/walkthrough.md) |

각 폴더를 프로젝트 루트로 열면 Claude Code가 그 안의 `.claude/`를 인식합니다.

```
ai-planning-agent/
├── README.md        # 전체 소개 + v1/v2 비교 (이 문서)
├── origin/          # 출발점: 직접 쓰던 요청서 프롬프트 원본
├── v1-harness/      # 기존 버전
│   ├── .claude/     #   CLAUDE.md · agents/ (7) · commands/ (8) · rules/
│   └── examples/
└── v2-template/     # 현재 버전
    ├── .claude/     #   CLAUDE.md · commands/ (5) · templates/ (6) · rules/ (frontend · tokens)
    └── examples/
```
